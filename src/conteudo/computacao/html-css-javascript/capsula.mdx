## O HTML: texto com etiquetas

No fim de 1990, Tim Berners-Lee, que trabalhava no CERN como contratado, especificou a linguagem HTML e escreveu o primeiro navegador e o primeiro servidor. O colega Robert Cailliau ajudou nos primeiros pedidos de verba. Em 1991, o documento "HTML Tags" descrevia **18 elementos**.

Depois vieram as versões: o **HTML 2.0** (24 de novembro de 1995, RFC 1866), o **HTML 3.2** (janeiro de 1997, a primeira versão padronizada só pelo W3C), o **HTML 4.0** (dezembro de 1997) e o 4.01 (dezembro de 1999). Em 2004 começou, no grupo WHATWG, o trabalho do **HTML5**, que virou recomendação do W3C em 28 de outubro de 2014. Em 2019 o W3C anunciou que o WHATWG ficaria como único responsável pelo padrão, mantido como um "padrão vivo" que muda aos poucos.

## O CSS: a roupa chega depois

Nos primeiros anos, a aparência de uma página vinha misturada no HTML, com etiquetas só para deixar o texto em negrito ou colorido. Isso virou bagunça. Em 10 de outubro de 1994, **Håkon Wium Lie**, que trabalhava com Berners-Lee no CERN, propôs o **CSS**. Bert Bos é considerado co-criador. O **CSS1** foi publicado em 17 de dezembro de 1996, com fontes, cores, espaçamentos, bordas e posicionamento básico. O CSS2 veio em 1998.

## O JavaScript: a página ganha vida

Em 1995, **Brendan Eich**, contratado pela Netscape, criou o JavaScript. Ele saiu primeiro como **LiveScript**, num teste (beta) do navegador Navigator em setembro de 1995, e foi renomeado para JavaScript no lançamento de 4 de dezembro. Apesar do nome, **não tem relação** com a linguagem Java: só compartilham um estilo parecido de escrever. O próprio Eich via o nome como uma escolha de marketing da Netscape, na época da bolha da internet.

Em novembro de 1996 a Netscape entregou o JavaScript à organização Ecma International, e a primeira especificação do **ECMAScript** saiu em junho de 1997. Em 2009, Ryan Dahl criou o **Node.js**, que permite rodar JavaScript fora do navegador, e isso aumentou muito o uso da linguagem em servidores.

## 1. Três camadas, três trabalhos

Na cápsula anterior você viu que o **front-end** é a parte que o navegador mostra. Ele é feito de três ingredientes:

- **HTML**: o **conteúdo e a estrutura**. "Aqui há um título, ali um parágrafo, aqui um botão."
- **CSS**: a **aparência**. "O título é grande e azul, o botão é redondo."
- **JavaScript**: o **comportamento**. "Quando tocarem no botão, conte uma curtida."

Cada camada pode existir sem as outras, mas elas funcionam melhor juntas. Uma página só com HTML é feia, mas **funciona e é legível**. É por isso que o HTML é a base.

## HTML: o esqueleto

O HTML é feito de **elementos**, marcados por **etiquetas** (*tags*) entre sinais de menor e maior. A maioria tem uma etiqueta de **abertura** e uma de **fechamento**, como `<p>` e `</p>`. Entre as duas fica o **conteúdo**. Algumas etiquetas não têm conteúdo e se fecham sozinhas, como a de quebra de linha, `<br>`.

<AnatomiaDeUmaTag />

Um **atributo** acrescenta informação à etiqueta, no formato `nome="valor"`. Atributos comuns: `id`, `class`, `lang` e `title`. Num link, o atributo `href` diz para onde ele leva.

<ExemploResolvido titulo="Lendo uma etiqueta">
  <Passo>Veja: `<a href="https://exemplo.com">Visite</a>`.</Passo>
  <Passo>A abertura é `<a ...>` e o fechamento é `</a>`.</Passo>
  <Passo>O atributo é `href="https://exemplo.com"`: **1** atributo.</Passo>
  <Passo>O conteúdo é "Visite", que é o texto visível.</Passo>
</ExemploResolvido>

<Exercicio enunciado="Em <a href='https://exemplo.com'>Visite</a>, quantos atributos há? (número)" resposta="1" dica="Procure algo no formato nome=valor." resolucao="Só o href. São 1 atributo." />

<Exercicio enunciado="Quantas etiquetas (contando abertura e fechamento) há em <p>oi</p>? (número)" resposta="2" dica="Uma abre, outra fecha." resolucao="São 2 etiquetas: <p> e </p>." />

## Etiquetas que dizem o que o texto é

O bom HTML descreve o **significado** do conteúdo (isso é um título, isso é um parágrafo, isso é uma lista), e não o aspecto. As etiquetas servem para o navegador **interpretar** o conteúdo: o navegador **não mostra** as etiquetas, ele as usa para saber o que fazer.

<EtiquetasHtml />

O significado ajuda muito: leitores de tela (usados por pessoas cegas) e buscadores dependem das etiquetas para entender a página.

<Aprofundar titulo="A estrutura de todo documento HTML">
Todo documento HTML começa com a declaração `<!DOCTYPE html>`, que ajuda o navegador a usar o modo certo de interpretação (o "modo padrão", e não um modo antigo de compatibilidade). Depois vem o elemento `<html>`, que contém duas partes: o `<head>` (a cabeça, com informações *sobre* a página, como o título da aba) e o `<body>` (o corpo, com tudo o que aparece na tela).

Num exemplo mínimo: `<html>`, dentro dele `<head>` com `<title>`, e `<body>` com um `<h1>` e um `<p>`. É o esqueleto de todo site que você visita.
</Aprofundar>

## CSS: regras de aparência

Uma folha de estilo é uma lista de **regras**. Cada regra tem um **seletor** (quem recebe o estilo) e um **bloco de declarações** (o que mudar). Cada declaração é uma **propriedade**, dois pontos e um **valor**.

Um exemplo: a regra `h1 { color: red; }` deixa **todo** título `h1` vermelho. Trocar `red` por `blue` muda todos de uma vez. É essa a grande vantagem do CSS: **um lugar só** para mudar o visual do site inteiro.

Os valores podem ser palavras (`red`), números com unidade (`200px`, `80%`) ou cores (nomeadas, em hexadecimal, RGB ou HSL).

## Seletores: quem recebe o estilo

Os principais seletores:

- **Por elemento:** `p` pega todos os parágrafos.
- **Por classe:** `.aviso` (com **ponto**) pega tudo que tem `class="aviso"`.
- **Por id:** `#topo` (com **cerquilha**) pega o elemento com `id="topo"`, que deve ser único.
- **Combinados:** `p.aviso` pega só parágrafos que também têm a classe `aviso`.

## A cascata: quando duas regras brigam

Várias regras podem tentar mudar a **mesma coisa**. Quem ganha? O "C" de CSS vem de *Cascading* (em cascata): existe uma ordem de prioridade. O que importa é a **especificidade**: quanto mais específico o seletor, mais forte. A força cresce nesta ordem: **elemento** (mais fraco), **classe**, **id** e, por último, o estilo escrito **na própria etiqueta** (o mais forte).

<CascataCss />

<ExemploResolvido titulo="Quem vence?">
  <Passo>O texto é `<p id="topo" class="aviso">`.</Passo>
  <Passo>Regra por elemento: `p { color: blue }`. Regra por classe: `.aviso { color: green }`. Regra por id: `#topo { color: red }`.</Passo>
  <Passo>O id é mais específico que a classe, e a classe mais que o elemento.</Passo>
  <Passo>Vence o **id**: o texto fica vermelho.</Passo>
</ExemploResolvido>

<Exercicio enunciado="Entre uma regra por classe e uma regra por elemento, qual vence? (classe ou elemento)" resposta="classe" dica="A mais específica." resolucao="A classe é mais específica que o elemento, então a regra por classe vence." />

<Exercicio enunciado="Entre uma regra por id e uma regra por classe, qual vence? (id ou classe)" resposta="id" dica="O id é único: o mais específico dos seletores." resolucao="O id vence a classe." />

<Aprofundar titulo="Como a especificidade é calculada">
A especificidade é uma sequência de quatro números, do mais forte ao mais fraco. Um seletor de **elemento** (como `h1`) vale 0,0,0,1. Uma **classe** (como `.uva`) vale 0,0,1,0. Um **id** vale 0,1,0,0. O estilo na própria etiqueta (atributo `style`) vale 1,0,0,0. Quando os seletores se combinam, os valores se somam coluna por coluna.

Por exemplo, `p.aviso` vale 0,0,1,1 (um elemento e uma classe), e por isso vence `p` sozinho (0,0,0,1) e perde para `#topo` (0,1,0,0). Se a especificidade empata, vale a regra que vem **por último** no arquivo. E acima de tudo isso existe o `!important`, que deve ser usado com muito cuidado.
</Aprofundar>

## Por que separar conteúdo e aparência

O CSS foi pensado para **separar conteúdo e apresentação**. Isso traz vantagens: o HTML fica mais simples, vários arquivos HTML podem **dividir o mesmo arquivo de estilo** (que o navegador guarda em memória para não baixar de novo), dá para ter estilos diferentes para tela, impressão ou leitura por voz, e a acessibilidade melhora. O CSS também permite o **design responsivo**: o mesmo conteúdo se adapta a telas de tamanhos e orientações diferentes (celular em pé, computador deitado).

<Aprofundar titulo="Design responsivo e consultas de mídia">
O mesmo site precisa ficar bom num celular de 375 pixels e num monitor de 1.280. O CSS permite escrever regras que só valem **em certas condições**, como "se a tela for larga". Essas condições se chamam **consultas de mídia** (*media queries*), listadas como um módulo do CSS3, recomendado em junho de 2012. Este app usa essa ideia: os estilos são escritos primeiro para o celular e depois adaptados para telas maiores.
</Aprofundar>

## JavaScript: o comportamento

O JavaScript é uma linguagem de programação que roda no navegador. Todo grande navegador tem um **motor de JavaScript** embutido. Em 2025 cerca de **98,9%** dos sites usavam JavaScript para o comportamento no navegador.

Ele conversa com a página por meio do **DOM** (*Document Object Model*), uma representação da página que o navegador monta a partir do HTML, em forma de árvore. O JavaScript pode ler e **mudar** essa árvore: trocar um texto, esconder um elemento, adicionar um item à lista.

O truque central é o **evento**. Um evento é "algo que aconteceu": um clique, um toque, uma tecla apertada. O programador registra um **ouvinte**: "quando este botão for clicado, execute esta função".

<OuvinteDeCliques />

<ExemploResolvido titulo="O contador de curtidas">

  <Passo>O JavaScript registra um ouvinte: "quando clicarem no botão, some 1 ao contador".</Passo>
  <Passo>Você toca 3 vezes. O ouvinte roda 3 vezes.</Passo>
  <Passo>O DOM é atualizado: o número na tela agora é **3**. Sem o ouvinte, o botão ficaria parado.</Passo>
</ExemploResolvido>

<Aprofundar titulo="JavaScript não é Java">
O nome confunde. As duas linguagens têm uma aparência de código parecida (o estilo "C"), mas são muito diferentes por dentro. O JavaScript nasceu como LiveScript e ganhou o nome para aproveitar a fama do Java na época, uma decisão de marketing da Netscape. Hoje, a linguagem é padronizada pelo nome **ECMAScript**, e as versões novas do JavaScript seguem esse padrão.
</Aprofundar>

<Aprofundar titulo="JavaScript também roda no servidor">
O JavaScript nasceu no navegador, mas em 2009 Ryan Dahl criou o **Node.js**, que junta o motor V8 (o mesmo do Chrome), um laço de eventos e funções de entrada e saída num programa independente. Com ele dá para escrever o **back-end** em JavaScript também. Antes disso, tentativas de usar JavaScript no servidor existiam, mas ficaram restritas. Depois do Node.js, a linguagem passou a ser muito usada fora do navegador.
</Aprofundar>

## Como as três trabalham juntas

Quando o navegador recebe uma página, ele lê o **HTML** e monta o **DOM**. Em seguida, lê o **CSS** e decide a aparência de cada elemento. Por fim, roda o **JavaScript**, que pode mudar o DOM a qualquer momento, e então o navegador **atualiza a tela**.

O JavaScript costuma também fazer pedidos ao servidor (a conversa com o back-end da cápsula anterior) sem recarregar a página, e atualizar só um pedaço da tela com a resposta. Foi isso que o Gmail e o Google Maps mostraram na prática, e que ganhou o nome de **Ajax** em 2005.

## Por que HTML, CSS e JavaScript juntos?

Dá para fazer sites de muitas formas, mas essas três são as únicas que **todo navegador entende sem instalar nada**. O front-end moderno usa bibliotecas e ferramentas (como React, Angular e Vue.js) para organizar telas grandes, mas por baixo, no final, o navegador recebe **HTML, CSS e JavaScript**. Entender esses três é entender o chão sobre o qual tudo é construído.

<Resumo>

- **HTML** é o esqueleto: elementos com etiquetas de abertura e fechamento, atributos (`nome="valor"`) e conteúdo.
- **CSS** é a roupa: regras com seletor e declarações. Seletores por elemento, `.classe` e `#id`.
- **Cascata:** quando regras brigam, ganha a mais específica (elemento < classe < id < estilo na etiqueta).
- **JavaScript** é o movimento: ouve eventos (cliques, toques) e muda a página pelo DOM.
- O navegador lê o HTML, monta o DOM, aplica o CSS e roda o JavaScript.
- Conteúdo faltando é HTML, visual estranho é CSS, botão parado é JavaScript.

**Um pouco de história.** Tim Berners-Lee especificou o HTML no fim de 1990 (o documento de 1991 tinha 18 elementos). Håkon Wium Lie propôs o CSS em 1994 e o CSS1 saiu em 1996. Brendan Eich criou o JavaScript em 1995 na Netscape (primeiro como LiveScript), e o padrão ECMAScript veio em 1997. O Node.js (2009) e o HTML5 (2014) completam a história até hoje.

</Resumo>
